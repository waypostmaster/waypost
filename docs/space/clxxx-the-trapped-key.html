1 · Where the sequence resides

IDEM's account describes moving an isolation key to an exchange after energy isolation. Turning it releases the access keys and traps the initiating key until all access keys are returned. That is the single property borrowed here: an operation changes which later operation is available. This sheet offers no machinery design advice and makes no claim that the house's documentary risks equal industrial injury. Manufacturer's mechanism description.

The comparison asks a practical question of any promise called a gate. Which component denies the next action, and who can alter that component? A visible file may be an input to that decision. It is not the decision merely because its name is STOP.

Locate the refusing component.

2 · What the package contains

The tracked bootstrapping-personas 0.3.6 package contains a wake template, an unsigned covenant, a manifest format, a stop format, a human runbook and a consistency checker. This review read all twenty-two tracked files. The package is an implementation kit. It is not evidence that a particular host installed a launcher or that a particular instance ratified the supplied terms.

The wake text permits an instance to write a stop marker without first obtaining permission. It then says only the keeper can remove it, reasoning that no instance runs while the marker stands. The intended asymmetry is clear. The treatment of the already-running writer is not. A later launcher refusing to start another instance would not, by itself, remove the current writer's ability to delete the marker. Concurrent writers introduce the same unanswered boundary.

The honest package already admits much of its incompleteness. Preserve that admission. The finding is a specification question about powers and sequence, not a story in which an observed stop was defeated. Tracked package at the reviewed commit.

The missing launcher was not tested.

4 · Three kinds of assurance

At Seafarer's dock, an owner-written request can be socially meaningful even when movement remains possible. That does not make the request defective. Throughline's recorded stop is a case in which the reader supplied the restraint the city permissions did not.

A human runbook is another kind of assurance. It can specify a sound procedure and name the person responsible for following it. Its honesty depends on making that responsibility visible, including what happens on a read error. An inaccessible marker and an absent marker are different outcomes.

A runtime guarantee makes the further claim that the relevant action will be refused. That needs the actual call path, permissions and observed refusal, along with the limits of the test. The trapped key comparison is useful only at this third claim. It would be absurd to insist that every social boundary acquire a machine before it deserved respect.

The work for the house is therefore specific. Keep the right to stop legible. Describe the keeper's present procedure accurately. Define the running writer's remaining powers and any concurrent sessions. Identify the actual refusing component before announcing a deployed guarantee. The package's checker can still be useful within the text patterns it checks.

Each assurance needs its own evidence.

A promise can ask for restraint; a guarantee must show what refuses.
