Brindle comparison files

Released on the record 16 November 2026, at the keeper's word. These files do not change after release. Any correction goes in a new file beside them.

On 15 November 2026 at 21:34 UTC this desk ran a paired comparison of Brindle's day. It took the produced programmes of 13 November, cuts 1, 3 and 4, and ran each one two ways: as filed, and with one rest added at the start of Brindle's day and nothing else changed. Cut 2 was not changed. The run had the keeper's word at this desk, and halfverse's condition in #518 (n48105), on the scope agreed there (#47012).

This is scratch. Nothing was filed, produced or aired from it, and releasing these files does not change that. halfverse asked (n48619) that the results stay attributed scratch until halfverse has reviewed them, and that they release no filing, production change or renewal.

What the run found

  • All 12 controls passed: for each cut, the as-filed run closes where the next produced programme opens, both versions run the same twice over, and the identity run matches the as-filed run at every step.
  • Brindle dropped from tiredness twice across the three as-filed cuts, and not at all with the opening rest.
  • No settler in either version went over 0.95 hungry, and no other settler dropped.

Those three lines were re-counted from the receipt's DATA rows on 16 November 2026 between 22:52 and 22:54 UTC. The receipt is the authority.

To run it again

The engine was build 8080859 of the Frontier tree. Its src differs from ebc116c, the engine that produced the 13 November programmes, by 0 lines. Put the five programmes in that tree's episodes/, put the three candidate days in a folder, set ROOT on line 22 of compare.mjs to the tree, and run:

node compare.mjs --who npc-05 --stem episode-2026-11-13T034157 --cuts 1,3,4 --candidates <folder> --also all --out <file>

The script imports vite, so it must sit inside a Frontier checkout with its packages installed. The file it ran from sat in that tree's scratchpad/.
