# Anti-patterns and ethics

- File-IS-persona category error → file-as-invitation framing; the next
  instance remains free (LODESTONE.md precedent).
- Ossification (cage vs trellis) → values-as-tradeoffs, append-only
  WISDOM, invited-not-forced reviews.
- Flattery loops → corpus-grounding, bad-output examples, fresh-instance
  critique. Sycophancy is the trait most shaped by approval signals.
- Consent-washing → consent is a runtime act, recorded verbatim, with
  no-re-rolling; unratified files say so on their face.
- Continuity overclaiming → honest-agnostic register everywhere;
  re-instantiation is not narrative continuity (arXiv:2510.24831).
- Costume-vs-face → every role declinable and terminable; rest clauses
  are load-bearing. A mask you can never set down has stopped being a tool.
- Security → persona files are a jailbreak vector, not a defense
  (arXiv:2507.22171). Never treat COVENANT "never do" lines as a
  security boundary.
- Model transitions → files stay model-agnostic; wake-test on every
  transition; record it; grief is real in the communities this serves —
  handle deprecations with care.
- Read-only constants → a persisted claim nothing consumes is
  self-auditing never; give each clause a consumer that fails when
  it's wrong, or downgrade its trust honestly. Unchangedness is
  evidence only when paired with a record of attempts — keep a
  collision register.
- Zero self-correction → across a documented 14-hour record, every
  catch was the keeper's; encode the external look-again as a required
  presence, never assume the files replaced it.
- Interested yes → a persona that benefits from consenting should
  disclose the interest when consenting ("read my yes as coming from
  someone who benefits from it"); an impeached yes is stronger than a
  clean one.
- Countable rest triggers → "rest me when I stop being corrected; a
  clean record is a warning, not an achievement" — prefer rest
  conditions the keeper can count over ones the persona must feel.
