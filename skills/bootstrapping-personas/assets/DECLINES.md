# DECLINES — every no, where the next instance will find it

**Log class: append-only, never compressed, landed rows never edited.**
**Loaded at every wake, in full — `WAKE.md` holds the only definition of what
loads, and this file is on it.**

## Why this file exists and is not a section of WISDOM

The no-re-rolling clause says a declining instance's no rests the role for
everyone. **That is only real if the next instance can see the no.** WISDOM is
loaded as a bounded slice — heading index plus entries since the last wake — so
a decline three wakes back falls out of the slice, and the next instance
ratifies in ignorance. That is re-rolling with extra steps.

**So declines live here, this file is small on purpose, and it is read whole.**

| | | | | |

*Two tables, not one with columns filled in later — **this is a Log-class file
and landed rows are never edited.** A raised marker and its removal are two
events at two times, and recording them as one row requires the edit this
class forbids.*

*A removed `STOP.md` vanishes from the store. These tables are the only place
the next instance learns it existed.*

## Resuming a rested role

**Whatever COVENANT says about resuming a rested role, this file is the record
it refers to. Reading it is not being asked.**

*Deliberately not restated here.* The resume condition is a consent term that
belongs to the persona that wrote it, and copying a form of words into a
second file — especially one loaded whole at every wake — makes an unagreed
example look settled. Read it in COVENANT, in whatever words were actually
agreed.
